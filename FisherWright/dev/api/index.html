FisherWright.FisherWright — Module
FisherWright

A high-performance forward-time Fisher-Wright population simulator for diploid individuals under mutation, crossover recombination, and random mating.

Haplotypes are represented as sorted, unique vectors of UInt32 mutation coordinates (supporting genomes up to $2^{32} \approx 4.29 \times 10^9$ base pairs), eliminating dense matrix allocations during generation stepping.

Main Features

  • Simulation: fisher_wright supports both explicit parameter configurations and BnGStructs.Species presets.
  • Fixed Mutation Tracking: Automatically extracts fixed substitutions during simulation via FisherWrightResult.
  • Dense Export: Convert sparse mutation representations into dense bit arrays and linkage maps via muts2bitarray and to_haplotype.
  • Targeted Chip Extraction: Directly extract genotype arrays at predefined marker coordinates without full genome materialization via extract_chip_bitarray or to_haplotype.
  • Recombination Landscapes: Custom or uniform crossover recombination maps via RecombinationMap and uniform_recombination_map.
  • Synthetic Data: Generate fast synthetic diploid genotypes and haplotypes with controlled allele frequencies via quickGT and quickHap.

FisherWright.fisher_wright — Function
fisher_wright(
    ne::Integer,
    nt::Integer,
    chr::Vector{<:Integer},
    mr::Float64;
    M = 1e8,
    mut_base = 1e8,
    result::Bool = false,
    fixation_interval::Int = 1,
    mutate::Bool = true,
    init = nothing,
    popsize = nothing,
    mating = RandomMating(),
    fitness = Neutral(),
    verbose::Bool = false,
    progress_interval::Integer = 100,
    rng::AbstractRNG = Random.default_rng(),
) -> Tuple{Vector{Vector{UInt32}}, Vector{UInt32}} | FisherWrightResult

Simulate a diploid Fisher-Wright population of size ne over nt generations under random mating, crossover recombination, and recurrent mutation, optionally with a changing census size, a fixed sex ratio, and selection at given sites.

Mutations are tracked as sorted, unique vectors of UInt32 genomic coordinates, supporting total genome lengths up to $2^{32} \approx 4.29 \times 10^9$ base pairs (bp).

Arguments

  • ne::Integer: Diploid population size (number of individuals, ne > 1), constant unless popsize is given; 2 * ne haplotypes are simulated. With popsize, ne is the size of the starting population.
  • nt::Integer: Number of generations to simulate (nt > 0).
  • chr::Vector{<:Integer}: Chromosome lengths in base pairs (all entries must be positive). Total genome length sum(chr) must be < 2^32.
  • mr::Float64: Expected mutation rate per mut_base base pairs per meiosis (must satisfy 0.01 < mr < 20.0).

Keywords

  • M = 1e8: Number of base pairs per Morgan (M > 0). A chromosome of length L experiences an expected L / M crossovers per meiosis.
  • mut_base = 1e8: Base pairs per unit of mutation rate mr (mut_base > 0). Decoupled from M so adjusting recombination does not alter mutation intensity.
  • result::Bool = false:
    • If false (default), returns (prt, cbp) where prt is the vector of 2 * ne haplotypes and cbp is cumulative chromosome end coordinates. Fixed mutations remain in all haplotypes.
    • If true, returns a FisherWrightResult, periodically extracting and tracking fixed substitutions to save memory and runtime. For the same rng state this is the same realization as result = false: FisherWright._with_fixed(res) equals prt.
  • fixation_interval::Int = 1: Frequency (in generations) to scan for and extract fixed substitutions when result = true.
  • mutate::Bool = true: If false, no new mutations are generated: the population evolves by drift and recombination only, and mr and mut_base are not used (mr must still lie in its valid range). Mating is drawn from rng exactly as with mutate = true, but meiosis shares the per-slot streams with the skipped mutation draws, so for the same seed the two settings give different realizations. Intended for validation runs that start from a polymorphic population given by init, for example heterozygosity decay $H_t/H_0 = (1 - 1/(2N_e))^t$; without init, a run with mutate = false stays monomorphic.
  • init = nothing: Starting population; nothing starts monomorphic. Either a Vector{Vector{UInt32}} of 2 * ne haplotypes (each sorted, unique, with positions in 1:sum(chr)), or a FisherWrightResult whose chromosome_ends equal cumsum(chr). Haplotypes 2i - 1 and 2i form individual i, the convention of the output, and these individuals are the parents of generation 1. init is copied and left unmodified. The substitutions of a FisherWrightResult are carried over when result = true and merged back into every haplotype when result = false; given as plain haplotypes, sites carried by all of them are extracted at the first fixation scan when result = true. See Continuing a run below.
  • popsize = nothing: Census size per generation; nothing keeps it at ne. Either a vector of nt integers or a function g -> N_g of the generation g = 1, …, nt, which is called once per generation before the run; every size must exceed 1. Generation g draws the parents of its N_g offspring from the N_{g-1} individuals of the previous generation (N_0 = ne), so the run returns 2 * N_nt haplotypes. bottleneck and growth build common trajectories. See Changing population size below.
  • mating = RandomMating(): Mating scheme. The default redraws sex as Bernoulli(½) per individual in every generation; RandomMating(nmale = m) or RandomMating(sexratio = p) fixes the number or the proportion of males instead. See Sex ratio below. FamilySize controls the distribution of family sizes, with one sire per dam.
  • fitness = Neutral(): Fitness model. SiteFitness(loci) selects on the sites of a FitnessLoci table, and TraitFitness(loci; σe, fitness) on a quantitative trait with the loci of a TraitLoci table; each draws parents with probability proportional to fitness within each sex, and requires result = true. See Selection below.
  • verbose::Bool = false: If true, writes a start banner and a progress line to stderr every progress_interval generations and at the last generation, reporting mean mutations per haplotype, accumulated substitutions (when result = true), elapsed wall time, and a linear ETA. On a terminal the line is updated in place; when stderr is redirected each report is a separate line.
  • progress_interval::Integer = 100: Generations between progress reports when verbose = true (must be positive).
  • rng::AbstractRNG = Random.default_rng(): Random number generator; see Reproducibility below.

Returns

  • When result = false:
    • prt::Vector{Vector{UInt32}}: Active haplotypes (2 * ne, or 2 * N_nt with popsize), each containing sorted, unique 1-based genomic mutation positions.
    • cbp::Vector{UInt32}: Cumulative chromosome end positions in base pairs (cumsum(chr)).
  • When result = true:
    • A FisherWrightResult containing active_haplotypes, chromosome_ends, accumulated substitutions, and the record of the run: the census size of every generation (census) and the realized number of males among its parents (males), from which effective_size gives the realized effective size. With selection it also holds the selected alleles (selected_haplotypes, selected_substitutions) and, per generation, the mean fitness of the parents and the mean and variance of its logarithm (mean_fitness, mean_log_fitness, var_log_fitness).

Details

  • Recombination & Independent Assortment: Recombination is modeled as a Poisson process along each chromosome with rate chr[i] / M. Independent assortment between chromosomes occurs with probability 0.5 at each chromosome boundary.
  • Mutation model: Each haplotype receives Poisson(sum(chr) / mut_base * mr) new mutations per generation at uniformly drawn positions. A new mutation at a position the haplotype already carries, or at a substituted (fixed and removed) position when result = true, has no effect, so both return modes describe the same population.
  • Multithreading & Reproducibility: Meiosis and mutation generation are parallelized using Threads.@threads. Each meiosis/haplotype slot owns a Xoshiro stream seeded once from rng at the start, and mating is sampled serially from rng, so a run is determined by the state of rng alone, independent of Threads.nthreads() and task scheduling. This holds for a fixed Julia version and package environment. The realization also depends on the variate algorithms of Julia's Random and of Distributions.jl, which can change between versions: randn differs between Julia 1.10 and 1.13, so Poisson draws with mean ≥ 6 (Distributions' PoissonADSampler; in practice the per-haplotype mutation count of most genome-scale runs) can differ, and the same seed then gives a different population. Record the Julia version and Manifest.toml with simulated data.
  • Continuing a run: With init, the population evolves for nt further generations from the given state, for example to burn in once and then start several replicates, or to follow a set of standing variants with mutate = false. The per-slot streams are seeded anew from rng on every call, so two calls of nt₁ and nt₂ generations are a valid realization of nt₁ + nt₂ generations but not the one a single call would give for the same seed. When init is a FisherWrightResult and result = true, the census record of the new generations is appended to that of init, so the result describes all nt₁ + nt₂ generations.
  • Changing population size: With popsize, the census size follows the given trajectory, for example a bottleneck or an expansion; mating, meiosis and mutation are otherwise as described above, and sex is redrawn in every generation, so the effective size of generation g follows the N_{g-1} parents. Working buffers and the per-slot streams are allocated once for the largest size of the run, so the realization for a given seed depends on that maximum: a trajectory that stays at ne reproduces the run without popsize, while two trajectories with different maxima share no random numbers.
  • Sex ratio: Sex is not inherited: it is assigned anew to each cohort when it reproduces, and every offspring draws a sire and a dam with replacement. By default the number of males among N parents is Binomial(N, ½) conditioned on both sexes being present, which gives $N_e \approx N - 1$. With mating = RandomMating(nmale = m) exactly m individuals, a uniformly random subset, are males in every generation, and with RandomMating(sexratio = p) exactly round(Int, p * N) (at least one of each sex); the effective size is then $4 N_m N_f / (N_m + N_f)$, so sexratio = 0.5 gives $N_e \approx N$ for even N. The fixed-sex schemes draw sex differently from rng, so they share no realization with the default for the same seed.
  • Selection: With fitness = SiteFitness(loci), the sites of loci are under selection: a genotype has fitness 1, 1 + h*s or 1 + s with zero, one or two copies of the derived allele, multiplied over sites. Selection is soft and acts within each sex: every offspring draws its sire among the males and its dam among the females with probability proportional to fitness, with replacement, so the census size is unchanged and only relative fitness within a sex matters. The derived alleles at the fitness loci are kept apart from the neutral mutations: they are returned in selected_haplotypes and, once fixed, selected_substitutions, they arise by mutation at rate loci.μ per site per haplotype per generation (never by the neutral mutation process, which may hit the same coordinates without effect on fitness), and they recombine with the neutral mutations as one haplotype. A selected allele of the starting population is given through init, as a FisherWrightResult with selected_haplotypes. If no member of a sex has positive fitness the run stops with an error. For the same seed, a run with selection shares no realization with a neutral run. With fitness = TraitFitness(loci; σe, fitness) the same holds for a quantitative trait: the genotypic value G sums 0, h*a and a over the sites of loci (substituted sites included), the phenotype is P = G + e with e ~ Normal(0, σe²) drawn serially from rng, and fitness is fitness(P), for example Stabilizing(θ, ω²) or Directional(β).
  • Allocation Efficiency: Working buffers (mutations, crossovers, mating assignments) are allocated once at start and reused, achieving zero steady-state per-generation allocations.

Examples

using FisherWright

# Simulate 50 individuals for 10 generations with two 100 kb chromosomes
haps, cbp = fisher_wright(50, 10, [100_000, 100_000], 1.0)
length(haps) # 100 haplotypes

# Return a structured result tracking fixed mutations
res = fisher_wright(50, 10, [100_000, 100_000], 1.0; result=true)
res.chromosome_ends

# Continue that population for 5 generations of drift without new mutations
res2 = fisher_wright(50, 5, [100_000, 100_000], 1.0; init=res, mutate=false, result=true)

# A bottleneck of 10 individuals for 5 generations, then recovery to 50
sizes = [fill(10, 5); fill(50, 15)]
haps, _ = fisher_wright(50, 20, [100_000, 100_000], 1.0; popsize=sizes)
length(haps) # 100 haplotypes

# 5 sires and 45 dams in every generation: Ne ≈ 4 * 5 * 45 / 50 = 18
haps, _ = fisher_wright(50, 20, [100_000, 100_000], 1.0; mating=RandomMating(nmale=5))

# Exponential growth from 50, as a function of the generation
haps, _ = fisher_wright(50, 20, [100_000, 100_000], 1.0; popsize=g -> round(Int, 50 * 1.05^g))

# Selection at 100 sites with s = 0.05, h = 0.5, new alleles at rate 1e-4 per site
loci = fitness_loci([100_000, 100_000], 100; s=0.05, μ=1e-4)
res = fisher_wright(50, 100, [100_000, 100_000], 1.0; fitness=SiteFitness(loci), result=true)
res.selected_substitutions

# The same two trajectories from the helpers
haps, _ = fisher_wright(50, 20, [100_000, 100_000], 1.0; popsize=bottleneck(50, 10, 1, 5))
haps, _ = fisher_wright(50, 20, [100_000, 100_000], 1.0; popsize=growth(50, 0.05))

fisher_wright(
    sp::Species,
    nt::Integer,
    mr::Float64 = 1.0;
    M = sp.M,
    mut_base = 1e8,
    result::Bool = false,
    fixation_interval::Int = 1,
    mutate::Bool = true,
    init = nothing,
    popsize = nothing,
    mating = RandomMating(),
    fitness = Neutral(),
    verbose::Bool = false,
    progress_interval::Integer = 100,
    rng::AbstractRNG = Random.default_rng(),
) -> Tuple{Vector{Vector{UInt32}}, Vector{UInt32}} | FisherWrightResult

Simulate a diploid Fisher-Wright population using species parameters from a BnGStructs.Species instance (such as Cattle, Pig, Chicken, or GenericSpecies).

The population size ne, chromosome lengths chr, and default base pairs per Morgan M are automatically extracted from sp:

  • ne = Int(sp.nid)
  • chr = sp.chromosome
  • M = sp.M

Arguments

  • sp::Species: Species definition from BnGStructs specifying diploid population size (nid), chromosome lengths (chromosome), and recombination scale (M).
  • nt::Integer: Number of generations to simulate (nt > 0).
  • mr::Float64 = 1.0: Mutation rate per mut_base base pairs per meiosis (0.01 < mr < 20.0).

Keywords

  • M = sp.M: Number of base pairs per Morgan. Defaults to sp.M.
  • mut_base = 1e8: Base pairs per unit of mr.
  • result::Bool = false: If true, returns a FisherWrightResult; otherwise returns (prt, cbp).
  • fixation_interval::Int = 1: Interval (in generations) to scan for and extract fixed substitutions when result = true.
  • mutate::Bool = true: If false, no new mutations are generated; see the method above.
  • init = nothing: Starting population of 2 * sp.nid haplotypes, or a FisherWrightResult; see the method above.
  • popsize = nothing: Census size per generation, as a vector of nt integers or a function of the generation; see the method above.
  • mating = RandomMating(): Mating scheme, for example RandomMating(nmale = 10); see the method above.
  • fitness = Neutral(): Fitness model, for example SiteFitness(loci) or TraitFitness(loci; σe, fitness); requires result = true; see the method above.
  • verbose::Bool = false: If true, reports progress to stderr; see the method above.
  • progress_interval::Integer = 100: Generations between progress reports when verbose = true.
  • rng::AbstractRNG = Random.default_rng(): Random number generator; see the method above.

Examples

using BnGStructs, FisherWright

sp = GenericSpecies("Example", Int32(20), UInt32[100_000, 100_000], UInt32(50_000_000))
res = fisher_wright(sp, 10; result = true)
res.chromosome_ends

FisherWright.RandomMating — Type
RandomMating(; nmale = nothing, sexratio = nothing)

Random mating between the sexes: each offspring draws its sire uniformly from the males and its dam uniformly from the females of the parental cohort, with replacement. Sex is assigned anew to every cohort when it reproduces, by one of three models:

  • RandomMating(): Bernoulli(½) per individual, conditioned on both sexes being present, so the number of males among N parents is Binomial(N, ½) truncated to 1:N-1. This is the default of fisher_wright.
  • RandomMating(nmale = m): exactly m males and N - m females, the males being a uniformly random subset of the cohort. Every parental cohort must have more than m individuals.
  • RandomMating(sexratio = p): exactly round(Int, p * N) males, limited to 1:N-1, for a proportion of males 0 < p < 1; the number of males then follows a changing census size.

With N_m males and N_f females the effective size of that generation is approximately 4 N_m N_f / (N_m + N_f) (Wright 1931).

FisherWright.FamilySize — Type
FamilySize(; dams = :random, sires = :random, nmale = nothing, sexratio = nothing)

Mating with controlled family sizes. In every generation the N_g offspring are split among the dams, and every dam is mated to one sire, so all her offspring are full sibs; the dams are split among the sires. A sire's family is the sum of the families of his dams. Sex is assigned to the parents as by RandomMating with the same nmale and sexratio.

dams sets how the offspring are split among the dams, and sires how the dams are split among the sires:

  • :equal: as equal as possible; when the split is not exact, the parents that receive one more are drawn at random.
  • :random: a uniform multinomial split, as each offspring choosing its dam (or each dam its sire) at random. Family sizes are then binomial, close to Poisson.
  • a positive number k: a multinomial split with weights drawn from Gamma(k, 1) for every parent in every generation (Dirichlet-multinomial counts, close to negative binomial). Smaller k means more variable families; as k → ∞ it approaches :random.

With n_d offspring per dam among N_f dams, two offspring share their dam with probability P_f = E[Σ n_d(n_d-1)] / (N(N-1)); they share their sire when they share their dam, or else when their dams share a sire. Two genes in different offspring then come from the same parent with probability a = (P_f + P_m)/4, and the effective size of the generation is about 1/(2a) + 1/2, which Hill's (1972) 8N/(V_m + V_f + 4) approximates.

The census size is not affected. FamilySize cannot be combined with selection yet. effective_size assumes random mating and does not apply to runs with FamilySize.

Examples

using FisherWright

# Equal dam families, 5 sires with equal numbers of dams
haps, _ = fisher_wright(50, 20, [100_000], 1.0; mating = FamilySize(dams = :equal, sires = :equal, nmale = 5))

# Highly variable dam families
haps, _ = fisher_wright(50, 20, [100_000], 1.0; mating = FamilySize(dams = 0.5))

FisherWright.bottleneck — Function
bottleneck(n, nb, start, duration; recovery = n) -> Function

Census trajectory g -> N_g for the popsize keyword of fisher_wright: nb individuals are born in each of the duration generations start, …, start + duration - 1, n in every generation before them and recovery in every generation after them.

Generation g draws its parents from the N_{g-1} individuals of the previous generation, so the nb individuals of a bottleneck generation are the parents of the next one: drift is increased in generations start + 1, …, start + duration.

All sizes must exceed 1, and start and duration must be positive. The function can also be broadcast over generations to build or combine trajectories as vectors, for example bottleneck(100, 10, 21, 5).(1:60).

Examples

using FisherWright

# 100 individuals, reduced to 10 in generations 21 to 25, then 100 again
res = fisher_wright(100, 60, [1_000_000], 1.0; popsize = bottleneck(100, 10, 21, 5), result = true)
res.census[20:28]   # N_19, …, N_27: 100, 100, 10, 10, 10, 10, 10, 100, 100

FisherWright.growth — Function
growth(n0, r; start = 0, limit = nothing) -> Function

Census trajectory g -> N_g for the popsize keyword of fisher_wright: geometric growth at rate r per generation from n0 individuals, N_g = round(Int, n0 * (1 + r)^(g - start)) for g > start and n0 up to generation start. r > -1; a negative r is a decline.

With limit, the size stops there: it is the ceiling of a growing population (r > 0) and the floor of a declining one (r < 0). Without it, a decline that reaches a size below 2 is rejected by fisher_wright, which names the generation, and growth is bounded only by memory: the run allocates for the largest size of the trajectory.

n0 should be the starting size ne of the run, so that the first generation continues from it. The function can be broadcast over generations to obtain the trajectory as a vector, growth(50, 0.05).(1:40).

Examples

using FisherWright

# 5% growth per generation from 50 individuals, up to 500
res = fisher_wright(50, 60, [1_000_000], 1.0; popsize = growth(50, 0.05; limit = 500), result = true)
res.census[[1, 2, 11, 61]]   # 50, 52, 81, 500

# Constant for 20 generations, then a 10% decline per generation down to 10
decline = growth(50, -0.1; start = 20, limit = 10)

FisherWright.SiteFitness — Type
SiteFitness(loci::FitnessLoci)

Multiplicative fitness over the selected sites of loci: an individual's fitness is the product over sites of 1, 1 + h*s or 1 + s for zero, one or two copies of the derived allele. Pass it as the fitness keyword of fisher_wright.

Selection is soft: fitness is evaluated on the adults of each generation, and each offspring draws its sire and its dam with probability proportional to fitness within each sex, with replacement. The census size is not affected, and only fitness relative to the other parents of the same sex matters.

FisherWright.FitnessLoci — Type
FitnessLoci(pos, s; h = 0.5, μ = 0.0)

Table of selected sites, fixed for a run.

  • pos: genome-wide positions of the sites, strictly increasing.
  • s: selection coefficient of the derived allele at each site (a number for all sites, or one per site), s ≥ -1.
  • h: dominance at each site (a number or one per site), with 1 + h * s ≥ 0.
  • μ: mutation rate to the derived allele per site per haplotype per generation; 0 means the selected alleles of a run are those of its starting population.

A genotype at one site has fitness 1, 1 + h*s and 1 + s with zero, one and two copies of the derived allele; see SiteFitness for how sites combine. Sites are biallelic and there is no back-mutation: a mutation at a site the haplotype already carries has no effect.

Fields

pos::Vector{UInt32}, s::Vector{Float64}, h::Vector{Float64}, μ::Float64.

FisherWright.fitness_loci — Function
fitness_loci(chr, nsites; s, h = 0.5, μ = 0.0, rng = Random.default_rng()) -> FitnessLoci

Draw nsites distinct selected sites uniformly over a genome with chromosome lengths chr and build their FitnessLoci table.

  • s: a number, used for every site, or a univariate distribution from Distributions.jl, from which one coefficient per site is drawn (the distribution of fitness effects), for example -Gamma(0.2, 0.05).
  • h: a number, or a function s -> h applied to each coefficient.
  • μ: mutation rate per site per haplotype per generation.

The draws come from rng only, so the table is reproducible and can be kept with the simulated data as the true effects.

Examples

using FisherWright, Distributions, Random

loci = fitness_loci([1_000_000, 1_000_000], 200; s = -Gamma(0.2, 0.05), μ = 1e-5, rng = Xoshiro(1))

FisherWright.TraitFitness — Type
TraitFitness(loci::TraitLoci; σe = 0.0, fitness)

Selection on a quantitative trait. Each generation, every adult has the genotypic value G given by loci (the sum over sites, including sites whose derived allele was fixed and moved to the substitutions), the phenotype P = G + e with e ~ Normal(0, σe²) drawn anew for every individual and generation, and the fitness fitness(P). fitness is Stabilizing, Directional, or any function that returns a non-negative number. Pass it as the fitness keyword of fisher_wright.

Selection is soft and acts within each sex, as for SiteFitness: every offspring draws its sire among the males and its dam among the females with probability proportional to fitness, with replacement.

The environmental deviations are drawn serially from the rng of the run, before mating, so a run does not depend on the number of threads.

Examples

using FisherWright, Distributions

chr = [1_000_000, 1_000_000]
loci = trait_loci(chr, 200; a = Normal(0, 0.2), μ = 1e-4)
f = TraitFitness(loci; σe = 1.0, fitness = Stabilizing(0.0, 5.0))
res = fisher_wright(100, 500, chr, 1.0; fitness = f, result = true)
res.mean_genotypic[end], res.var_genotypic[end]

FisherWright.TraitLoci — Type
TraitLoci(pos, a; h = 0.5, μ = 0.0)

Table of the loci of a quantitative trait, fixed for a run.

  • pos: genome-wide positions, strictly increasing.
  • a: effect of the derived allele at each site (a number for all sites, or one per site): the genotypic value of the derived homozygote. Any finite value.
  • h: dominance at each site (a number or one per site): the heterozygote has value h * a. With h = 0.5 the site is additive.
  • μ: mutation rate to the derived allele per site per haplotype per generation; 0 means the trait alleles of a run are those of its starting population.

The genotypic value of an individual is the sum over sites of 0, h*a and a for zero, one and two copies of the derived allele, so that an individual without derived alleles has value 0. Sites are biallelic and there is no back-mutation.

Fields

pos::Vector{UInt32}, a::Vector{Float64}, h::Vector{Float64}, μ::Float64.

FisherWright.Stabilizing — Type
Stabilizing(θ, ω²)

Gaussian stabilizing selection on the phenotype P: fitness exp(-(P - θ)^2 / (2ω²)), with optimum θ and width ω² > 0. For use in TraitFitness.

FisherWright.FisherWrightResult — Type
FisherWrightResult(active_haplotypes, chromosome_ends, substitutions, census, males,
                   selected_haplotypes, selected_substitutions,
                   mean_fitness, mean_log_fitness, var_log_fitness,
                   mean_genotypic, var_genotypic, mean_phenotypic, var_phenotypic)
FisherWrightResult(active_haplotypes, chromosome_ends, substitutions;
                   selected_haplotypes, selected_substitutions)

Structured container holding the output of a Fisher-Wright simulation, keeping active haplotypes, chromosome breakpoints, and fixed substitutions together with the census record of the run.

Fields

  • active_haplotypes::Vector{Vector{UInt32}}: Active haplotype mutation positions (two per individual of the last generation). Each inner vector contains sorted, unique 1-based base pair coordinates of segregating mutations.

  • chromosome_ends::Vector{UInt32}: Cumulative chromosome end positions in base pairs (1-based, strictly increasing).

  • substitutions::Vector{UInt32}: Sorted, unique positions of mutations that reached fixation across all haplotypes and were removed from active_haplotypes during simulation.

  • census::Vector{Int}: Census sizes $N_0, N_1, …, N_{nt}$ of the recorded generations: census[1] is the starting population and census[g + 1] the number of individuals born in generation g.

  • males::Vector{Int}: males[g] is the realized number of males among the census[g] parents of generation g; the remaining census[g] - males[g] parents are females.

  • selected_haplotypes::Vector{Vector{UInt32}}: for each haplotype, the sorted positions of the derived alleles it carries at the fitness loci of a run with selection (SiteFitness); empty vectors in a neutral run. These alleles are kept apart from the neutral mutations in active_haplotypes.

  • selected_substitutions::Vector{UInt32}: sorted positions of fitness loci whose derived allele reached fixation and was removed from selected_haplotypes.

  • mean_fitness::Vector{Float64}, mean_log_fitness::Vector{Float64}, var_log_fitness::Vector{Float64}: fitness of the parents of each generation, entry g describing the same census[g] adults as males[g]: the arithmetic mean of fitness, and the mean and the (sample) variance of its logarithm. Fitness is absolute, relative to an individual without any derived allele at the fitness loci, so substituted sites are included. In a neutral run these are 1, 0 and 0. If an adult has zero fitness (a lethal genotype), the mean of the logarithm is -Inf and its variance NaN.

  • mean_genotypic::Vector{Float64}, var_genotypic::Vector{Float64}, mean_phenotypic::Vector{Float64}, var_phenotypic::Vector{Float64}: under TraitFitness, the mean and (sample) variance of the genotypic value and of the phenotype of the parents of each generation, as for the fitness record; NaN for generations without a trait model.

A run continued from a FisherWrightResult through the init keyword of fisher_wright appends its generations to the record of that result, so generations are numbered from the first call; started from plain haplotypes, the record begins anew. The three-argument constructor builds a result without a record, with census holding the number of individuals only and males empty; its keywords give the selected alleles of a starting population, for example one copy of a new allele.

FisherWright.effective_size — Function
effective_size(result::FisherWrightResult, generations = eachindex(result.males)) -> Float64

Effective population size realized by the sex numbers recorded in result, over the given generations (one generation or a collection of them; all generations of the run by default).

Generation g has $N_m$ = result.males[g] male and $N_f$ = result.census[g] - result.males[g] female parents, and each offspring draws its sire and its dam uniformly with replacement, so two genes in different offspring derive from the same parent with probability $a_g = 1/(4N_m) + 1/(4N_f)$. The effective size of that generation is $1/a_g = 4N_mN_f/(N_m + N_f)$ (Wright 1931), and over several generations it is the harmonic mean, $1/\bar{a}$.

This is the value determined by the realized census record, not an estimate from the genetic data. It assumes RandomMating: the result does not record the mating scheme, and under FamilySize, whose families are not those of random mating, the value is not the effective size (see the docstring of FamilySize for its coalescence probability). Selection, which also changes the variance of family size, is not accounted for either. It depends on the parents only, not on the number of offspring. At constant sex numbers the asymptotic rate of loss of heterozygosity, $1/(2N_e)$, corresponds to $N_e \approx 1/a + 1/2$, because the two genes of one individual come from different parents.

Errors

  • Throws an ArgumentError if generations is empty, as for a result built without a census record, and a BoundsError for a generation outside the run.

Examples

using FisherWright

res = fisher_wright(50, 20, [100_000], 1.0; mating = RandomMating(nmale = 5), result = true)
effective_size(res)        # 4 * 5 * 45 / 50 = 18.0
effective_size(res, 1:10)  # the first ten generations

FisherWright.muts2bitarray — Function
muts2bitarray(
    muts::Vector{Vector{UInt32}},
    cbp::Vector{UInt32};
    flip::Bool = false,
    include_fixed::Bool = false,

Convert sparse per-haplotype mutation coordinate vectors into a dense boolean presence/absence matrix (BitMatrix) and an accompanying marker linkage map DataFrame.

Arguments

  • muts::Vector{Vector{UInt32}}: Vectors of 1-based mutation positions per haplotype (length nhp = 2 * ne). Each inner vector must be sorted and unique.

  • Throws an ArgumentError if cbp has more than 127 chromosomes (the chr column is Int8).

FisherWright.RecombinationMap — Type
RecombinationMap(cbp, interval_ends, interval_rates)

Piecewise-constant crossover recombination map defined across chromosomes.

Stores cumulative chromosome ends, interval boundaries, and expected crossover rates (Poisson intensities) per interval. Pre-computes Poisson samplers upon construction to maximize performance in meiosis loops (cobp!).

Fields

  • cbp::Vector{UInt32}: Cumulative chromosome end positions in base pairs.
  • interval_ends::Vector{Vector{UInt32}}: End coordinates for each recombination interval within each chromosome.
  • interval_rates::Vector{Vector{Float64}}: Expected crossover counts (Poisson mean) per interval.
  • samplers::Vector{Vector{Poisson{Float64}}}: Pre-constructed Poisson distributions for efficient sampling.

Invariants

  • The outer lengths of cbp, interval_ends, and interval_rates must match the number of chromosomes.
  • cbp must be strictly increasing and positive.
  • Within each chromosome, interval_ends[i] and interval_rates[i] must have the same non-zero length.
  • interval_ends must be strictly increasing and terminate at cbp[i].
  • interval_rates must be non-negative.

FisherWright.cobp! — Function
cobp!(dest::Vector{UInt32}, map::RecombinationMap; rng::AbstractRNG = Random.default_rng()) -> Vector{UInt32}

Sample crossover positions from a RecombinationMap into dest in place, emptying dest first and returning it.

Details

  • Within each interval of map, the number of crossover events is drawn from a Poisson distribution with the interval's rate, and coordinates are distributed uniformly at random over the gaps the interval owns. A breakpoint c switches parent between positions c - 1 and c, so an interval ending at e owns gaps p+1:e, where p is the previous interval end on the same chromosome, or the chromosome's first position for the first interval. A one-bp chromosome has no gaps.
  • Each chromosome boundary (map.cbp[i]) is added as a crossover breakpoint with probability 0.5, simulating independent chromosome assortment during meiosis.
  • Reusing dest across successive meioses eliminates allocations.

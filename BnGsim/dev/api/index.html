BnGsim.FounderPopulation — Type
struct FounderPopulation

Holds the complete state of a sampled founder population for breeding simulations.

Fields

  • species::Species: Biological species definition (e.g. Cattle, Pig).
  • haplotype::Haplotype: Base genome haplotypes (nlc × 2nid).
  • map::VariantMap: Variant genomic map (VariantMap from BnGStructs).
  • markers::LocusSet: Marker chip panel (LocusSet from BnGStructs).
  • qtl::TraitQTL: Single-trait QTL architecture.
  • h2::Float64: Target heritability.
  • tbv::Vector{Float64}: True Breeding Values for the n founder individuals.
  • phenotypes::Vector{Float64}: Simulated phenotypes (y = TBV + e).
  • pedigree::DataFrame: Pedigree with columns :id, :sire, :dam (sire/dam = 0 for founders).

Note: fp.marker_indices is also supported as a property alias returning fp.markers.loci.

BnGsim.HistoricalSpec — Type
struct HistoricalSpec

A historical (pre-founder) population run with FisherWright.fisher_wright.

Fields

  • name::String: arm label, e.g. "F2".
  • ne::Int: diploid population size, constant over the run.
  • nt::Int: number of discrete, non-overlapping generations.
  • mr::Float64: mutations per 1e8 bp per meiosis (μ = mr × 1e-8).
  • chromosome::Vector{UInt32}: autosome lengths in bp.
  • M::Float64: bp per Morgan (1e8 is 1 cM/Mb).

Model, as implemented by FisherWright with its neutral defaults: diploid, dioecious Wright-Fisher population with random union of gametes; infinite-sites mutation; Poisson crossovers without interference; independent assortment of chromosomes; the genome starts monomorphic, so nt determines how close the run is to mutation-drift equilibrium (about 10ne generations for the frequency spectrum, much less for LD at short distances).

BnGsim.MeiosisRecord — Type
MeiosisRecord

Crossovers of the gametes made by one call of make_progeny!. Gamete g is column g of the offspring Haplotype (2i-1 from the sire, 2i from the dam of mating i).

  • parent[g]: the parent (column of the mating plan) that made it;
  • phase[c, g]: true if chromosome c starts on the parent's second haplotype;
  • crossovers(rec, g): genome-wide positions of its crossovers, in increasing order within each chromosome.

With the parental records this determines the founder origin of every segment, the input of segment-level IBD.

BnGsim.Population — Type
Population

Animals of a breeding program, one row per animal in order of birth. Animal ids are 1:n and equal the row; nothing is ever removed, so the equality holds (invariant I4 holds trivially).

Fields:

  • sire, dam (0 = unknown), male, generation (the birth cohort, i.e. the time step of birth; founders are 0; with discrete generations it is the generation number), exit (the first time step at which the animal is dead or culled; typemax(Int32) while it lives);
  • tbv, phenotype, ebv: n × k matrices, one column per trait, of genetic values, phenotypes (NaN in the sex that does not express the trait) and the last evaluation;
  • blocks, first: the haplotypes, one Haplotype per cohort, with first[t + 1] the id of the first animal of cohort t;
  • qtl (one TraitQTL per trait), traits, Lr (lower-triangular factor of the true residual covariance matrix, $R = L_rL_r'$), key;
  • G0, R0: the genetic and residual covariance matrices of the next evaluation (the true ones of the founders unless re-estimated);
  • meioses: the crossover records of each cohort (meioses[t] for cohort t ≥ 1, parents as population ids) when the scheme records them, nothing otherwise; see founder_segments.

Build one with founder_population, extend it with step!, and save or restore it with save_checkpoint and load_checkpoint.

BnGsim.Scheme — Type
Scheme(; noff, nsire, ndam, evaluation = :pblup, selection = :truncation,
       K = NaN, λ = 0.0, κ = 0.0, ub = 1.0, chip = Int32[], blend = 0.05,
       max_sire_age = 0, max_dam_age = 0, reml = false, weights = Float64[],
       survival = Float64[], cull_unselected = false, genotyped_cohorts = 0,
       ocs = :fixed, ΔF = NaN, record_meiosis = false)

A selection and mating scheme, applied every time step:

  • noff: offspring per step (one per mating);
  • nsire, ndam: parents selected by truncation, and the number of each sex used by random selection;
  • evaluation: :tbv (true values, an oracle), :phenotype (own records), :pblup (animal model with the pedigree relationship matrix), :gblup (animal model with $G^* = (1-w)G + wA$, w = blend, G VanRaden at the loci chip with base allele frequencies from the founders), :ssgblup (single-step, $H^{-1}$ of Legarra et al. 2009 and Christensen & Lund 2010 from RelationshipMatrices.hinv, with the animals of the last genotyped_cohorts cohorts genotyped at the loci chip (0: all animals), $G$ as for :gblup and blended with $A_{22}$ by blend; with every animal genotyped it equals :gblup). With several traits the animal model is multi-trait, with an intercept per trait and residuals correlated within animals;
  • weights: the index weights $w$ (one per trait; empty: all 1). Candidates are ranked on $I = w'\hat a$, which with economic values as weights and multi-trait BLUP EBVs is the optimal index for the aggregate genotype $H = w'g$ (Henderson 1963). With :phenotype it is $w'y$, a fixed-weight index, not the optimal phenotypic index;
  • selection: :truncation (best nsire males and ndam females on the index, equal numbers of offspring), :ocs (optimum contributions; see ocs below), :rocs (Breeding.rocs with λ, κ, the prediction error covariance of the candidates' index as Ω, and an upper bound ub on each parent's contribution, in rocs units where each sex contributes ½; ub = 0.5/nsire with λ = κ = 0 is truncation selection), or :random (nsire and ndam chosen at random, a neutral reference);
  • max_sire_age, max_dam_age: the oldest age, in time steps, at which an animal can be selected as a parent (age 0: born in the current step). 0 for both gives discrete generations; larger values give overlapping generations, with all eligible ages competing on one criterion. With :ocs and :rocs the contributions are those of the candidates to the next cohort, without the age-class weighting of Meuwissen & Sonesson (1998) or Bijma & Woolliams (2000); the constraint then does not bound the long-term rate of inbreeding exactly;
  • reml: if true, the covariance components of :pblup and :gblup are re-estimated by AI-REML (Breeding.jl) from all records before every evaluation, starting from the previous estimates, once every trait has a record on an animal with a known parent (before that, as with the founders' records alone, genetic and residual components are not separable and the true values are used); otherwise the true values of the founders are used. With all records and the full pedigree, REML estimates the base-population components even under selection (Sorensen & Kennedy 1984; infinitesimal model). Several traits are estimated with AI steps on the Cholesky factors (param = :cholesky of Breeding.reml), which keeps the estimates positive definite; early estimates may lie on the boundary (e.g. a genetic correlation near ±1 after one cohort);
  • ocs: the constraint of :ocs. :fixed: Breeding.TM1997 with $c'Ac \le K$ at every step (average coancestry $K/2$). The others hold the rate of inbreeding at the target ΔF per generation (see ocs_contributions): :cohort constrains the mean kinship of the newborn cohort; :age_year the mean kinship of the population at the next step, age classes weighted by their remaining expected contributions (Meuwissen & Sonesson 1998; optiSel), with the per-step increase set by the estimated generation interval; :age_generation the same with the generation interval of the contributions being chosen (a per-generation constraint, Sonesson et al. 2000). With discrete generations the three coincide;
  • record_meiosis: keep the crossover records of every cohort in pop.meioses, for realized IBD from founder segments (founder_segments); about 8 bytes per crossover;
  • survival: survival[a + 1] is the probability that an animal alive at age a survives to age a + 1 (the last entry for all older ages; empty: no deaths). Deaths are drawn between steps (Domain.SURVIVAL), independently of genotype and records (missing at random), so they bias neither BLUP nor REML;
  • cull_unselected: if true, eligible animals of age 1 or more that are not selected as parents at a step are culled. Young candidates (age 0) are kept for the next step. Culling depends on the EBV, so the animals left are a selected sample; BLUP and REML with all records and the pedigree account for that.

Dead and culled animals are not candidates, and a record taken at an age the animal did not reach is missing.

BnGsim.SimKey — Type
SimKey(seed; replicate = 0, generation = 0, domain = 0, stage = 0, entity = 0, subcounter = 0)
SimKey(base::SimKey; field = value, ...)

The coordinate of one random stream:

FieldTypeMeaning
seedUInt64master seed of the scenario
replicateUInt32replicate number
generationUInt32generation or time step
domainUInt16Domain code: meiosis, phenotype, mating, …
stageUInt16a stable code of the event within the domain, never a position in a schedule
entityUInt32the animal, mating or locus the draws are for; 0 when population-scoped
subcounterUInt64a further index, e.g. sire (0) or dam (1) gamete

The second form copies base and replaces the named fields, so callers derive keys from a scenario key.

keyed_rng turns a key into a random number generator. Two keys that differ in any field give unrelated streams.

Layout

The Philox4x64-10 key is (seed, replicate | KEY_LAYOUT << 32) and the counter is (generation << 32 | domain << 16 | stage, entity, subcounter, 0). The four 64-bit outputs are the state of a Random.Xoshiro. This layout is fixed; the golden test in test/keys.jl guards it.

BnGsim.continue_population — Method
continue_population(res::FisherWrightResult, ns, mr; M = 1e8, mut_base = 1e8,
                    rng = Random.default_rng()) -> FisherWrightResult

Continue a FisherWright population for length(ns) further generations with census size ns[g] in generation g, e.g. a decline from the historical size to a breed-like size before founders are sampled. This is fisher_wright(...; init = res, popsize = ns): the same model (dioecious Wright–Fisher, Poisson crossovers at 1/M per bp, infinite-sites mutation at mr / mut_base per bp per meiosis) with a census size that may change every generation.

The result does not depend on the number of threads. Mutations that fix during the continuation move to substitutions, and the per-generation records of res are extended. An empty ns returns res.

Realizations for a given rng differ from BnGsim 0.1.0, which ran its own serial loop on FisherWright internals.

BnGsim.eqtl — Method
eqtl(hap::Haplotype, loci, R, ts::AbstractVector{<:AbstractTrait};
     rng = Random.default_rng(), atol = 1e-8) -> MultiTraitQTL

Sample additive QTL effects of several traits at shared loci so that the genetic values of the individuals in hap have mean 0, standard deviations ts[i].σₐ and correlation matrix R, exactly in that sample.

Effects of trait i are drawn from ts[i].da, independently across traits. With $\mathbf{C}$ the sample covariance matrix of the resulting genetic values and $\boldsymbol\Sigma = \mathbf{D}\mathbf{R}\mathbf{D}$ ($\mathbf{D}$ the diagonal of the σₐ) the target, the effect matrix $\mathbf{A}$ is replaced by $\mathbf{A}\mathbf{L}_C^{-\top}\mathbf{L}_\Sigma^\top$ ($\mathbf{L}$ the Cholesky factors). The transform is upper triangular: the effects of trait 1 are only rescaled and keep the shape of their distribution; those of trait i > 1 are linear combinations of the draws for traits 1…i, so only their first two moments are controlled. Means go to the intercepts.

Needs at least as many QTL as traits and more individuals than traits. The realised covariance is checked and an ArgumentError is thrown if it misses Σ by more than atol (relative to the largest variance).

BnGsim.eqtl — Method
eqtl(hap::Haplotype, loci, t::AbstractTrait; rng = Random.default_rng(), atol = 1e-8) -> TraitQTL

Sample additive QTL effects of trait t at loci (a LocusSet or locus indices) and scale them so that the genetic values of the individuals in hap, the base population, have standard deviation t.σₐ and mean 0.

  • Effects are drawn from t.da and multiplied by one factor, so their distribution keeps its shape and sign (a Gamma da stays positive).
  • The mean is set by the intercept of the returned TraitQTL (BnGStructs.TraitQTL(...; intercept)), not by shifting the effects.
  • t.σₐ is the standard deviation (with the n − 1 divisor) of the genetic values in hap. It includes the covariances between QTL from linkage disequilibrium in that sample; the genic standard deviation, $\sqrt{\sum 2p(1-p)a^2}$, differs from it. trait_summary reports both.

The realised values are checked after scaling and an ArgumentError is thrown if they miss the target by more than atol (relative), or if the QTL are monomorphic in hap.

BnGsim.evaluate! — Method
evaluate!(pop::Population, scheme::Scheme) -> Union{Nothing, MME}

Fill pop.ebv for every animal and trait by the scheme's evaluation at the current time step. For :pblup, :gblup and :ssgblup the mixed-model equations over the records available (see observed) are built with Breeding.jl and solved directly: $y = 1\mu + Za + e$ with $\sigma^2_e$ scaling for one trait; for several traits, records stacked trait-major with an intercept per recorded trait, $\operatorname{var}(a) = G_0 \otimes K$ and $R_0$ among the records of one animal (missing records handled exactly). The covariance components are pop.G0 and pop.R0, first re-estimated by REML if scheme.reml. The equations are returned for prediction error variances. :phenotype needs every trait recorded at birth in both sexes.

BnGsim.founder_population — Method
founder_population(hap::Haplotype, qtl::TraitQTL, trait::Trait, key::SimKey) -> Population
founder_population(hap::Haplotype, qtl::MultiTraitQTL, traits, key::SimKey; Re = I) -> Population

Cohort 0 of a breeding program: the individuals of hap, unrelated founders, with sexes drawn at random (Domain.MATING), genetic values from qtl and one phenotype per trait (Domain.PHENOTYPE). Each trait's residual standard deviation is fixed from the trait as $\sigma_e = \sigma_a\sqrt{(1 - h^2)/h^2}$, with $\sigma_a$ the trait's σₐ, so $h^2$ is the heritability in the founders; Re is the residual correlation matrix of several traits. key carries the seed and replicate; its other fields are set per draw.

The covariance components of the evaluations are those of the founders: $G_0 = D\,C\,D$, $D$ the diagonal of the traits' σₐ and $C$ the correlation matrix of the founders' genetic values (exactly the R of a multi-trait eqtl), and $R_0 = D_e R_e D_e$.

A trait's sex (0 females, 1 males, 2 both) limits its records to one sex; its age, a whole number of time steps, is the age at which a record becomes available to evaluations (0: at birth). Phenotypes are drawn for every animal and trait either way, from the animal's own keyed stream, so these settings change which records are seen, not the values drawn.

BnGsim.founder_summary — Method
founder_summary(xy, lmp; nchip = 20_000, chip_maf = 0.2, nqtl = 10_000, qtl_maf = 0.0,
                presample = 3, rare = 0.05, ld = (;), rng = Random.default_rng())
    -> (scalars::NamedTuple, sfs::DataFrame, ld::DataFrame, chip, qtl)

Founder-level outcomes of plan §4.3 for one replicate of one arm. xy holds the founders' phased haplotypes at the loci segregating among them, lmp their map with sample frequencies (founder_haplotypes).

Chip and QTL loci are drawn as in the WCGALP pipeline (xyBnG founder_pop): presample × nchip chip candidates with sample MAF > chip_maf are set aside first, and the QTL are drawn from the loci with MAF > qtl_maf that are left, so the QTL are depleted of common loci when the founders have few of them. The chip is nchip of the candidates and nqtl QTL are kept. (The pipeline makes its final cut after the founder expansion, among the candidates that still meet the MAF condition; here it is made among the founders.) presample = 1 removes only the chip, which is what this function did before 2026-11-11 and does not describe the pipeline. Scalars:

  • nid, nseg: founders, segregating sites;
  • sum2pq: Σ2pq over all segregating sites (expected heterozygosity × sites);
  • n_maf02: sites with MAF ≥ 0.2, the pool for the chip;
  • chip_r2_adj: mean r² between adjacent chip markers on a chromosome, and chip_gap, their mean spacing (bp);
  • qtl_maf_mean, qtl_rare: mean QTL MAF and the fraction with MAF < rare;
  • qtl_rare_va: share of Σ2pq over QTL carried by QTL with MAF < rare, i.e. the expected share of V_A from rare QTL under i.i.d. effects;
  • qtl_maf02: fraction of QTL with MAF ≥ 0.2;
  • g_diag, g_offsd: mean diagonal and SD of off-diagonals of the founder-centred VanRaden G at the chip;
  • me: 1 / var(G off-diagonal), the effective number of independent chromosome segments implied by realized relationships (Goddard 2009).

sfs is the folded MAF spectrum in 0.05 bins; ld is ld_decay with keyword arguments ld.

BnGsim.generation_summary — Method
generation_summary(pop::Population, g; weights = ones(k), segs = nothing) -> NamedTuple

For cohort g: its size; mean, variance and genic variance $\sum 2p(1-p)a^2$ at the QTL of the genetic values (one trait), or of the aggregate genotype $H = w'g$ with weights as $w$ (several traits, then also mean_<name>, var_<name> per trait and the genetic correlation rg_<a>_<b> of each pair within the cohort); mean pedigree inbreeding F and mean pedigree coancestry $\bar\theta_g$ over all pairs of the cohort, self-coancestry $(1 + F_i)/2$ included (founders unrelated and non-inbred); the loss of heterozygosity Fhet; the number of animals alive at step g (all cohorts); and, given the founder segments segs (founder_segments(pop, mm), which step! passes when the scheme records meioses), the mean realized inbreeding Fseg of the cohort, the proportion of the genome at which an animal's two haplotypes descend from the same founder haplotype (its expectation is the pedigree F).

Fhet is $1 - (1 - \bar\theta_0)\,\bar H_g/\bar H_0$ over all loci, with $\bar H$ the mean of $2p(1-p)$ from the cohort's own allele frequencies and $\bar\theta_0 = 1/(2n_0)$ the founders' mean coancestry. Each $\bar H_g$ is a sample estimate whose expectation is $H(1 - \bar\theta_g)$, $H$ the heterozygosity of the population the founders were drawn from, so without selection the expectation of Fhet is the mean coancestry $\bar\theta_g$. Under selection, Fhet − coancestry measures the extra loss of heterozygosity at loci linked to QTL; both carry drift noise that is large when few chromosome segments segregate.

BnGsim.ld_decay — Method
ld_decay(xy, lmp; minmaf = 0.05, edges = [5e3, 1e4, 2e4, 5e4, 1e5, 2e5, 5e5, 1e6, 2e6, 5e6],
         npairs = 20_000, M = 1e8, rng = Random.default_rng()) -> DataFrame

Haplotype r² between loci with sample MAF ≥ minmaf, in distance bins [edges[k], edges[k+1]) bp. For each bin, npairs pairs on the same chromosome are drawn by picking a random anchor locus and a random partner in the bin downstream of it.

Columns: lo, hi, d (mean distance of the sampled pairs), n, r2 (mean), r2adj = r2 - 1/nh (sample-size correction for nh phased haplotypes), and the Sved (1971) LD-based effective size ne = (1/r2adj - 1) / (4c), c = d/M Morgan, which refers to about t = 1/(2c) generations ago (Hayes et al. 2003). ne is NaN when r2adj ≤ 0.

BnGsim.make_progeny! — Method
make_progeny!(offspring::Haplotype, parents::Haplotype, plan, mm::MeiosisMap, key::SimKey;
              record = false) -> offspring, or (offspring, MeiosisRecord)

Make one offspring per row of the mating plan plan (n × 2, sire and dam as columns of parents): row i writes haplotypes 2i-1 (from the sire) and 2i (from the dam) of offspring, which must have at least 2n haplotypes and the loci of parents.

The draws of gamete (i, k) come from keyed_rng(SimKey(key; domain = Domain.MEIOSIS, entity = i, subcounter = k - 1)), k = 1 for the sire and 2 for the dam. The result is a function of key, the plan and the parents only: it does not depend on the number of threads or on the order in which rows are processed. Several offspring of one pair are separate rows. The caller sets seed, replicate, generation and stage of key; its domain, entity and subcounter are overwritten.

See MeiosisMap for the meiosis model.

BnGsim.ocs_contributions — Method
ocs_contributions(u, Θ, b, K, male) -> (c, feasible, value)

Contributions c (each sex summing to ½, all $\ge 0$) maximising $u'c$ subject to $f(c) = c'\Theta c + 2b'c \le K$: optimum contribution selection (Meuwissen 1997) with the linear term $b$ that the fixed contributions of older age classes add.

The problem is convex. It is solved exactly by homotopy in the weight $\nu$ of the gain: $c(\nu)$ minimises $f(c) - 2\nu u'c$ under the sex constraints and $c \ge 0$. For a fixed set of zero contributions $c(\nu) = y + \nu x$ is linear. The path starts at $\nu = \infty$, the best male and the best female (ties by position), and $\nu$ is lowered from one breakpoint to the next (a candidate entering when its multiplier reaches zero, or a contribution reaching zero) until $f(c(\nu)) = K$. The free set stays as small as the solution, so a breakpoint costs a factorisation of the order of the number of parents. If the path reaches $\nu = 0$ first, $c(0)$ minimises $f$, the bound cannot be met, and it is returned with feasible = false. value is $f(c)$ at the solution.

BnGsim.phenotype! — Method
phenotype!(
    ped::DataFrame,
    trts::Union{AbstractTrait, AbstractVector{<:AbstractTrait}};
    R_e::Union{Nothing, AbstractMatrix{<:Real}} = nothing,
    rng::AbstractRNG = Random.default_rng(),
) -> DataFrame

Generate phenotypes in ped (columns "ft_" * t.name) from true breeding values ("tbv_" * t.name) for one or more BnGStructs.AbstractTrait objects (aTrait or tTrait).

  • Environmental standard deviation for trait t is $\sigma_e = \sigma_a \sqrt{(1 - h^2) / h^2}$.
  • If R_e (a residual correlation matrix across trts) is given, environmental deviates are drawn jointly with correlation R_e.

BnGsim.save_checkpoint — Method
save_checkpoint(path, pop::Population) -> path

Save the whole state of pop at a time-step boundary. A run continued from load_checkpoint with the same scheme and MeiosisMap is identical to an uninterrupted one, because every draw is keyed by coordinate and nothing else carries state between steps.

The file is a magic, the versions of BnGsim and Julia, and the population in Julia's Serialization format. That format is not guaranteed across Julia or package versions, so a checkpoint is for resuming a run, not for archiving results; write haplotypes with BnGStructs.write_haplotypes for that.

BnGsim.select_parents — Method
select_parents(pop::Population, scheme::Scheme, m) -> (sires, nsire_off, dams, ndam_off, info)

Parents and their numbers of offspring (each list summing to scheme.noff), among the living males of age at most scheme.max_sire_age and females of age at most scheme.max_dam_age at the current time step (the youngest cohort only, with the default ages 0), ranked on the index $w'\hat a$ (see Scheme). m is the MME returned by evaluate! (nothing for :tbv and :phenotype); :rocs takes the prediction error covariance of the candidates' index from it. Every ranking breaks ties by ascending id (invariant I1a). info is empty except for the dynamic OCS constraints, where it holds the bound, the constrained kinship reached, the generation interval used and whether the bound could be met (ocs_bound, ocs_kinship, ocs_L, ocs_feasible).

BnGsim.trait_summary — Method
trait_summary(hap::Haplotype, qtl::Union{TraitQTL, MultiTraitQTL}) -> NamedTuple

Genetic summary of the individuals in hap for the traits of qtl (additive architecture), one entry per trait:

  • mean, var: mean and variance (n − 1 divisor) of the genetic values;
  • genic: genic variance $\sum_j 2p_j(1-p_j)a_j^2$, with $p_j$ the allele frequency at QTL $j$ in hap; var − genic is the contribution of linkage disequilibrium (and of the n − 1 divisor);
  • cor: correlation matrix of the genetic values (1 × 1 for one trait).

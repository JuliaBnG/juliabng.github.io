Command line

bin/bngsim runs a scenario from the shell. It is the interface the planned web service will call, so its arguments, output and exit codes are versioned (CLI interface 1) separately from the package.

bngsim validate SCENARIO.json
bngsim estimate SCENARIO.json
bngsim run SCENARIO.json --out DIR [--replicates A:B] [--memory-limit SIZE] [--checkpoint-every K]
           [--archive none|chip|qtl|all]
bngsim resume DIR
bngsim merge DIR... --out DIR
bngsim version [--json]

The script starts Julia in the environment of the checkout (or BNGSIM_PROJECT) with BNGSIM_THREADS threads (default: all) and calls cli. From Julia, BnGsim.cli(["run", "s.json", "--out", "out"]) does the same and returns the exit code.

Output

Every command writes one JSON object to stdout and diagnostics to stderr, so a caller reads the result from stdout and the reason for a failure from both.

  • validate prints {"status": "valid", "scenario_sha256", ...}, or {"status": "invalid", "errors": [...]} with every problem of the scenario and its path.

  • estimate prints the expected peak memory, a conservative bound, the disk written and a rough run time (Resource estimate).

  • run writes three files to DIR, which must not exist or must be empty (results are never overwritten):

    • scenario.json, the canonical scenario (scenario_json);
    • summary.csv, the per-step summaries of every replicate (run_scenario; columns in generation_summary and step!, among them the QTL at which the favourable allele is segregating, fixed or lost, the realized selection intensity of each sex, genomic inbreeding Fgrm and, with report_reliability, the candidates' mean reliability), numbers in Julia's shortest round-trip form;
    • aggregate.csv, per time step over the replicates, the mean, standard deviation and standard error of every summary, and of quantities derived within each replicate: genetic gain dG, rates of inbreeding dF (pedigree) and dFhet (loss of heterozygosity), and the variance and genic variance relative to the first step, var_ratio and genic_ratio (aggregate);
    • provenance.json: the canonical scenario and its SHA-256, the seed and replicates, the BnGsim, CLI and schema versions, the Julia and package versions, the SHA-256 of the active manifest, the operating system, CPU, host and threads, the start and end times, and the SHA-256 of the other two files.

    It then prints {"status": "completed", "outputs": [...], ...}. With --memory-limit SIZE (bytes, or a number with K, M, G or T), a scenario whose memory bound exceeds SIZE is refused before it runs.

  • With --archive PANEL, run also writes an archive of each replicate (pedigree, records, true and estimated breeding values, QTL, and PLINK genotypes at the loci of PANEL) to DIR/archive/r<N>/.

  • resume DIR continues a run that was stopped or killed (below).

  • version --json prints the versions and the manifest hash.

scenario.json and summary.csv depend only on the scenario, the replicates, the Julia and package versions, and the compiler flags. They are byte-identical whatever the number of threads: for examples/minimal.json, checked at 1 and 8 threads. Flags that change the compiled code change the last bits of floating-point sums: Julia started with --check-bounds=yes (as Pkg.test does) gives other last digits than the default. Everything about the run itself is in provenance.json.

Replicates on several hosts

bngsim run ... --replicates A:B runs part of the replicates of a scenario, for example on several hosts, and bngsim merge DIR... --out OUT combines completed runs of the same scenario (the SHA-256 of their scenarios must agree) whose replicates do not overlap. OUT gets the scenario, the summaries ordered by replicate, the aggregate and a provenance that lists the runs merged. Since every replicate is keyed by its number, the merged summary.csv and aggregate.csv are byte for byte those of a single run of all the replicates, in whatever order the runs are merged or finished.

Stopping and resuming

While a run is unfinished its state lives in DIR/.bngsim-run/: the scenario, the shared historical population, the summaries of the replicates done, and a checkpoint of the one in progress. A file DIR/CANCEL (created by a user or the service) stops the run after the current time step: the state is saved and bngsim exits with code 7. SIGINT (Ctrl-C) and SIGTERM (as a job scheduler or kill sends it) to bin/bngsim do the same: the launcher creates DIR/CANCEL, so the run stops at the next step boundary, never inside a step. Before the run has saved any state (while Julia loads, or the scenario is checked) there is nothing to keep, and the launcher stops Julia at once; a second signal also stops it at once, with the last saved state kept (state files are written atomically, never half-written). The signals are handled by the launcher, not by Julia, so that they behave the same on every Julia version and number of threads. bngsim resume DIR removes DIR/CANCEL and continues. With --checkpoint-every K the state is also saved every K steps, so that a process that is killed, or a host that goes down, loses at most K steps.

A resumed run gives the same scenario.json and summary.csv, byte for byte, as one that was never interrupted, since every random draw is keyed by its coordinate (replicate, step, animal) and nothing else carries over between steps. provenance.json lists each session (start, end, host, CPU, threads, and whether it was stopped or completed). run refuses a directory that holds an unfinished run. The state uses Julia's serialization, so it resumes only under the same BnGsim and Julia versions; it is for continuing a run, not for archiving.

Exit codes

CodeMeaning
0success
2usage: unknown command, missing or invalid arguments
3the scenario is missing, unreadable or does not validate
4refused: the output directory is not empty or holds an unfinished run, the replicates are outside the scenario's, or there is nothing to resume (or its state is from another version)
5refused before running: the memory bound exceeds --memory-limit
6the simulation stopped with an explicit error, e.g. fewer segregating loci than the panels ask for
7stopped at a step boundary by DIR/CANCEL (also created by bin/bngsim on SIGINT or SIGTERM); bngsim resume DIR continues
70internal error (a bug)

A run that fails before it saved any state, or is refused, writes no output directory (ExitCode).

Start-up time

The scenario and command-line paths are compiled into the package image when BnGsim is precompiled (a workload of two small scenarios), which takes about half a minute once per installation. After that, bngsim run examples/minimal.json takes about 3 s from the shell, start-up included, instead of about 35 s.

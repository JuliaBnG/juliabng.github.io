Output files

The files that bngsim writes are versioned: provenance.json and bngsim version --json carry outputs_version, now 1. Within a version, a file keeps its columns, in this order, for every scenario; new columns are only appended at the end of a table, so a reader that selects columns by name keeps working, and one that reads them by position keeps working for the columns it knows. A change that renames, removes, moves or redefines a column raises outputs_version.

Which optional columns a table has depends on the scenario (the number of traits, repeated records, the selection method, recorded meioses), as listed below; for one scenario the set is fixed.

Run directory

FileContent
scenario.jsonthe canonical scenario (scenario_json)
summary.csvone row per replicate and time step (below)
aggregate.csvone row per time step, over the replicates (below)
provenance.jsonthe run: versions, hashes, host, sessions (Command line)
archive/r<N>/with --archive: the archive of replicate N (below)

provenance.json holds scenario_sha256, the SHA-256 of the canonical text, and results_sha256, that of the content that determines the results (results_sha256): the canonical scenario without its name, number of replicates, schema keys and history directory, and without every key at its default. A key added in a later release, with a default that keeps earlier results, changes the canonical text of every scenario but not its results_sha256; bngsim merge accepts runs whose scenarios agree on it.

The last row of a replicate (the newest cohort, in which no selection took place) has NaN for the selection columns and 0 parents.

aggregate.csv

One row per time step (aggregate): generation, replicates, then for each column c of summary.csv after generation (in that order, replicate and history excepted) c_mean, c_sd, c_se; then the same three for the changes within a replicate: dG and dG_<t>... (several traits), dF, dFhet, var_ratio, genic_ratio. When the replicates aggregated include at least two histories with several replicates each (so this depends on the replicates, not only on the scenario), also histories (after replicates) and c_sdh, c_seh after each c_se.

History directory

bngsim history writes one file per history in FisherWright's result format and manifest.json (schema "bngsim-history", its own version 1): the parameters that determine the histories, the seed, and the file names with their SHA-256 (write_histories).
